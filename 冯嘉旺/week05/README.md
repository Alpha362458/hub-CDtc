# Week05：基于 Transformer 语言模型的 SFT

## 作业实现

参照 `week04/language_model.py` 的字符级自回归 Transformer，加载
`week04/best_model_transformer.pt` 做全参数监督微调（SFT）。
本作业的代码、训练输出全部位于 `week05`；不修改、导入执行或覆盖 `week04` 的文件。
使用已有 Conda 环境 `py312`，无需下载大模型，也不使用 LoRA。

| 文件 | 用途 |
| --- | --- |
| `sft_model.py` | 与 week04 权重兼容的 Transformer、字符编码、权重扩展 |
| `train_sft.py` | JSONL 读取、回答区域损失、训练与验证、最佳权重保存 |
| `generate_text.py` | 加载 SFT 权重，根据指令生成单轮回答 |
| `sft_train.jsonl` | 老师提供的 3,000 条训练样本，保持原样 |
| `sft_val.jsonl` | 老师提供的 200 条验证样本，保持原样 |
| `best_model_sft.pt` | 训练后生成的最佳 SFT 权重 |
| `sft_history.json` | 微调前基线、每轮 Loss/PPL 和运行参数 |

## SFT 与 Week04 的区别

Week04 是连续文本的下一字符预测，对所有目标字符计算交叉熵。
Week05 仍然使用下一字符预测，但将每条指令和回答单独组织为：

```text
用户：{instruction}
助手：{output}<eos>
```

`<eos>` 是一个独立的结束 token，不是逐字编码的五个可见字符。
输入为整段序列去掉最后一个 token，目标为整段序列去掉第一个 token。
提示区域的目标设为 `-100`，通过
`CrossEntropyLoss(ignore_index=-100)` 只监督回答字符和 EOS：

```text
原序列：提示字符 ... 最后一个提示字符 回答第1字 回答第2字 EOS
输入 x：提示字符 ... 最后一个提示字符 回答第1字 回答第2字
目标 y：   -100  ...     回答第1字    回答第2字    EOS
```

尤其注意：最后一个提示字符的输出负责预测回答的第一个字符，不能将这一位置屏蔽。
损失可以写为：

```text
L = -1/N × Σ log P(回答目标字符 | 指令和此前字符)
```

其中 N 是未屏蔽的回答目标数，包含 EOS，不包含提示和补齐位置。
验证 PPL 为 `exp(回答区域平均交叉熵)`，不能直接与 week04 的普通语料 PPL 比较。

## 模型和数据处理

- 保留 week04 的字符嵌入、可学习位置嵌入、因果 Transformer、LayerNorm、线性输出层。
- 原检查点为 2 层、嵌入维度 128、4 个注意力头、前馈维度 512，旧字表有 4,000 个字符。
- 原字符编号不变，仅从训练集补充新字符和 `<pad>`、`<unk>`、`<eos>`。
- 旧嵌入和输出层对应行完整复制，新增行随机初始化；不从验证集扩充字表。
- 上下文默认由 64 扩展到 128，前 64 个位置嵌入保留，新增位置随机初始化。
- 验证或推理遇到词表外字符时映射到 UNK，不删除字符。
- 每条样本单独训练；批次在右侧动态补齐，PAD 目标设为 `-100`。
- 因果掩码使有效位置无法看到右侧补齐，不需要额外的 padding attention mask。
- 超长样本报错并提示增大 `--seq_len`，不静默截断答案。
- AdamW、梯度裁剪、自动选择 CUDA/MPS/CPU；默认微调学习率 `1e-4`。
- 每轮验证，保存训练轮次中验证 Loss 最低的模型；同时记录微调前基线。

## 运行方式

以下命令在项目根目录执行。先激活老师作业使用的 Python 环境：

```bash
conda activate py312
python "冯嘉旺/week05/train_sft.py" --epochs 10
```

默认路径相对于脚本所在目录解析，不依赖终端所在目录。
默认只读取 week04 检查点，模型另存到 `week05/best_model_sft.pt`，
训练记录写入 `week05/sft_history.json`。输出路径有检查，不能写入 week04，
也不能覆盖输入检查点或训练、验证数据。

若未激活 Conda，也可使用环境中的 Python 绝对路径：

```bash
/opt/anaconda3/envs/py312/bin/python "冯嘉旺/week05/train_sft.py" --epochs 10
```

生成回答：

```bash
python "冯嘉旺/week05/generate_text.py" \
  --instruction "给定两个数字，请选择其中的较大数并将其打印出来。 数字1: 238 数字2: 564" \
  --temperature 0 --max_new_tokens 60
```

`temperature=0` 为贪婪解码，便于对比实验；大于 0 时按温度采样。
遇到 EOS、生成字符上限或上下文上限时停止，并显示停止原因。
不会通过滑动窗口丢弃原始指令；较长指令留给回答的上下文空间更少。

小规模冒烟测试（临时模型不是正式作业训练结果）：

```bash
python "冯嘉旺/week05/train_sft.py" \
  --epochs 1 --limit_train 32 --limit_val 16 --batch_size 8 \
  --save /tmp/week05_sft_smoke.pt \
  --history /tmp/week05_sft_smoke_history.json
```

训练脚本加载的是预训练模型，并重新建立优化器。
SFT 检查点不包含优化器状态，不是精确断点续训文件。
可以用 `--pretrained "冯嘉旺/week05/best_model_sft.pt"` 继续微调，
但必须通过 `--save` 指定另一个输出文件，并保持或增大原上下文长度。
不要将后续轮次的局部历史误当作第一次训练的完整记录。

## 效果与数据限制

这是约 147 万参数的字符级模型，3,000 条 SFT 样本适合验证微调流程，
不保证获得通用问答、数学推理或可靠事实回答能力。
除了观察验证 Loss/PPL，还应人工检查生成答案，不能仅凭 PPL 判断正确率。

数据已检查：JSON 格式和必需字段有效，文件内部无完全重复样本，
训练集与验证集无相同指令重叠。但样例中存在错误或过时答案，例如：

- 验证样本声称 12 和 25 不互质且都能被 5 整除，实际上二者互质。
- 训练样本将 `23,45,67,89,12` 的标准差写为 `33.41`；
  总体标准差约为 `28.43`，样本标准差约为 `31.78`。
- “目前最受欢迎”之类的问题没有明确时间及来源，答案可能过时。

本次保留老师原始数据，不自动改写标签。错误标签会被模型学习，
也会影响验证指标的解释；如老师允许清洗，应该另存修正版数据后再训练。

## 本次全量训练结果

使用 `py312` 和 MPS，从 week04 预训练权重开始，完整训练 10 轮，
batch size 为 32，学习率为 `1e-4`，随机种子为 42。
最佳检查点来自第 10 轮，已保存到 `best_model_sft.pt`。
完整逐轮结果见 `sft_history.json`。

| 阶段 | 训练 Loss | 验证 Loss | 验证回答 PPL |
| --- | --- | --- | --- |
| 微调前（扩展字表和位置嵌入后） | 不适用 | 5.4961 | 243.73 |
| 第 1 轮 | 4.9738 | 4.4999 | 90.01 |
| 第 3 轮 | 4.1445 | 3.9903 | 54.07 |
| 第 10 轮 | 3.5587 | 3.5497 | 34.80 |

已验证正式检查点可以被推理脚本加载，并能生成回答直到 EOS。
但在贪婪解码样例中，对“从 238 和 564 中选择较大数”的指令，
模型回答为“这组数字的平均值为 1。”，并未正确完成任务。
因此本次结果证明 SFT 训练链路可用、验证损失下降，
不能证明模型已经具备可靠的指令遵循或数学能力。
